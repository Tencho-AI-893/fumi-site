# SM.Carma 採用ログ自動分析・レポート生成

毎月1日 朝8:00に、前月分の採用活動（Ichigo Navi / Qpuri / LP直接応募）を自動集計し、
スプレッドシートの「レポート」タブを更新、fumi@carma.jp 宛にメールでお知らせする仕組み。

Google Apps Script（GAS＝スプレッドシートを裏で自動操作する仕組み）で動く。
Claudeとのチャットだけでは「毎月自動実行」はできないため、GAS側に時間主導トリガー（決まった時刻に自動で処理を動かす予約）を設定する。

## セットアップ手順（初回のみ）

1. https://script.google.com にアクセスし、「新しいプロジェクト」を作る。
2. 左メニューの「エディタ」で `Code.gs` を開き、中身を全部消してこのフォルダの `Code.gs` の内容を貼り付ける。
3. 左メニューの歯車アイコン「プロジェクトの設定」→「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェックを入れる。
4. `appsscript.json` を開き、中身をこのフォルダの `appsscript.json` の内容に置き換える。
5. 上部の保存アイコンで保存する。
6. 関数選択のプルダウンで `initializeCarmaRecruitmentSystem` を選び、実行ボタン（▷）を押す。
7. 初回は権限確認の画面が出るので、「許可」を進める（自分のGoogleアカウントで実行することの確認）。
8. 実行が終わると、自分のメールアドレス宛に「セットアップ完了」メールが届く。そこにスプレッドシートのURLが書いてある。

以降は、そのスプレッドシートの「採用ログ」タブに、候補者への送信のたびに1行ずつ入力していく。
**既存の行・列は削除しないこと。追記のみ。**

列の並び：日付 / 候補者名 / 媒体（Ichigo Navi・Qpuri・LP直接応募から選択） / 開封（チェックボックス） / 返信（チェックボックス） / 面接（実施済み・未実施） / 結果（採用・不採用・選考中）

## 動作確認したいとき

関数選択で `manualRunForTesting` を選んで実行すると、今月分のデータで即座にレポートを試作できる
（本番の自動実行は前月分を対象にするが、これは動作確認用に今月分を対象にする）。

## 自動実行の仕組み

- `monthlyRecruitmentReport` が毎月1日 朝8:00に自動実行され、前月分のレポートを作る。
- 集計値はCOUNTIFS系とSUMIFS/SUMPRODUCT系の2通りの数式で独立計算し、両者が一致しない場合はレポート冒頭に警告を出す（詳細は隠しシート「検算_自動生成_編集不要」）。
- CSVは同じ内容を Google Drive の「reports」フォルダに `YYYY-MM.csv` として保存する（同名ファイルがあれば上書き）。
- 当月データが0件の場合は「データなし」のレポートのみ出し、改善提案欄は無理に埋めない。
- スプレッドシートが見つからない、「採用ログ」シートが見つからないなどの異常時は、レポート生成を中止して fumi@carma.jp にエラー内容をメールする。

## 設定値（変更したい場合は `Code.gs` 冒頭を編集）

- `REPORT_EMAIL`：レポート送付先。現在 `fumi@carma.jp` の1件のみ（個人情報を含むためCC/BCCでの拡散はしない）。
- `MINUTES_PER_REPLY`：Fumi-chanの1件あたり平均対応時間。初期値15分の仮置き。実測値が分かり次第この数値を更新する。
- `MIN_SAMPLE_SIZE`：媒体別比較で「サンプル数不足」と注記する閾値（初期値5件未満）。
